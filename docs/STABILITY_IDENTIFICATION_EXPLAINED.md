## 0. 一句话 + 一个类比

**一句话**：用 20 个不同的“随机抽样版本”各做一次同样的 LASSO 辨识，
看**哪些系数反复被判为“非零”**，把反复被判非零的那些固定下来，作为最终结构。

**类比**：你想知道一份考卷里“哪些题是必考知识点”。你让 20 位老师各自划重点
（每人手里的模拟卷略有不同，但教学大纲不变）。某知识点 20 位老师都划了 → 必考
（π = 1.0）；只有 3 位划了 → 大概不重要（π = 0.15）；10 位划了 → 存疑（π = 0.5）。
最后用“过半就保留”的规则定下重点清单。这就是本方法的全部思想。

## 1. 先扫清词汇

### 1.1 被辨识的到底是什么

每个相位组（stance / swing）的控制器是一个线性映射：

```
muscle excitation (9 个肌肉)  =  X(t) · β  +  b
                                26×1    26×9   1×9
```

- `X(t)` 是 **26 个特征**：9 个 `lCEN`（归一化肌纤维长度）+ 9 个 `fATN`
  （归一化 MTU 力）+ 8 个骨盆/关节角度与角速度。设计矩阵直接用 `X`
  （旧版记作 `A = X*M`，`M` 为单位阵，已移除，全文统一用 `X`）；
- `β` 是 **26×9** 的系数矩阵：第 j 列对应第 j 块肌肉；
- `b` 是 **1×9** 的偏置（bias）。

### 1.2 什么是 mask（0-1 图）

`β` 里有 26×9 = **234 个格子**。LASSO 会把很多格子压到**恰好 0**。
把“非零”记 1、“为零”记 0，就得到一张 **234 个 0/1 的图**，代码里叫 `mask`：

```matlab
mask = abs(beta) > nzTol;      % nzTol = 1e-5
```

- `mask(i,j) = 1`：特征 i 对肌肉 j **有作用**，这个系数交给 CMA-ES 去调；
- `mask(i,j) = 0`：**结构零**，永远不参与优化。

这就是你说的“哪些参数有值、哪些参数无值”。**它是本方法的唯一输出目标**；
系数的具体数值只是附带产物。

> 运行时是硬约束：`unpack_lasso_reflex_params.m` 每帧都执行
> `beta(~mask) = 0`，而扁平参数向量的长度在 `load` 时就已经按 mask 固定。
> CMA-ES 没有任何路径能改变这张图。

### 1.3 “两个 mask 完全相同”是什么意思

就是**两张 26×9 的 0/1 矩阵，234 个格子逐一相等**。

```matlab
mask1 = [1 1 0; 0 1 0];       % 假设 2×3
mask2 = [1 1 0; 0 1 1];
isequal(mask1, mask2)         % false（第 2 行第 3 列不同）
```

哪怕只差 1 个格子，也不算“完全相同”。所以我在报告里说“**20 个种子里没有任何
两份完全一样**”，指的是这种逐格相等的判据——它非常苛刻，234 个格子里有
5–10 个格子随数据抖动，就不可能逐格全等。

### 1.4 Jaccard 相似度

衡量两个 mask **有多像**（而不是“是否完全一样”）：

```
J(A, B) = |A ∩ B| / |A ∪ B|
        = (两个都是 1 的格子数) / (至少一个是 1 的格子数)
```

- 完全一样 → 1.0；完全不相交 → 0；一半重叠 → 约 0.5。
- 用格子数说话，就不受“有几个 1”影响。

**举例**（4 个格子）：`A = [1 1 0 0]`，`B = [1 1 0 1]`
→ 交集 `{1,2}` 有 2 个，并集 `{1,2,4}` 有 3 个 → `J = 2/3 ≈ 0.67`。

它比“完全相同”有用得多：能回答“两个种子选出的结构大概有六七成重叠”，
而不是“一样/不一样”这种二元判断。

### 1.5 覆盖率（coverage）

Jaccard 是**对称**的，但“共识 mask 有没有丢掉某个种子需要的东西”是**不对称**的：

```
coverage(seed) = |seed ∩ consensus| / |seed|
```

即“这个种子选出的条目里，有多少被共识保留下来”。本次运行是 0.78 / 0.82，
意思是共识保留了每个种子约八成条目，丢了约两成（那些被不到一半种子选中的条目）。

### 1.6 RMSE：相对什么？

**目标** `y`：每块肌肉的**清洗后 excitation**（无量纲，0–1），来自 MocoInverse 解。

**预测**：`ŷ(t) = max(X(t)·β + b, c)`，其中 `c = 0.01` 是 censoring floor
（低于它的值统一按 0.01 处理，因为实测 excitation 在 0 附近没有信息量）。

**加权 RMSE**：

```
RMSE = sqrt( Σ_t w_t · (y_t − ŷ_t)²  /  Σ_t w_t )
```

- `w_t` 是 `sampleWeight`：正常样本 1，Moco 分段接缝/无效样本 0（本数据 3001 帧
  里有 10 帧是 0，0.33%）；
- 计算是**按相位组分别做**的（stance 只用 stance 的样本，swing 只用 swing 的）；
- 单位就是 excitation，所以 `0.02` ≈ “平均差 2% 的 excitation”。

稳定性报告里出现的两种 RMSE，必须分清：

| 名字 | 在哪些样本上算 | 用途 |
|---|---|---|
| 种子的 RMSE | 在**重采样后的样本**上（in-bag） | 只用于诊断；**偏乐观**（自己抽的数据自己拟合） |
| 全量参照 RMSE | 在**全部 3001 帧**上，用未冻结的常规拟合 | 唯一的公平基准 |
| 冻结后 RMSE | 在**全部 3001 帧**上，用共识 mask 重拟合 | 与上一行同口径比较 |

`rmseDelta` 就是最后两行的相对差：

```
rmseDelta(muscle) = (RMSE_冻结 − RMSE_未冻结) / RMSE_未冻结
```

本次是 `[+0.23, −0.13, −0.34, −1.35, −3.16, +0.05, −2.30, +1.09, +3.59]` %，
平均 **−0.26%**：冻结共识结构几乎没有代价，个别肌肉有 ±3% 的涨落。

### 1.7 π（pi）：入选频率

对 234 个格子中的每一个：

```
π(i,j) = （K 个种子里，mask(i,j)=1 的次数） / K
```

K = 20，所以 π 只能取 0, 0.05, 0.10, …, 1.00。
**π 就是“票数比例”**：π = 0.65 表示 13/20 个种子认为这个格子该有值。

### 1.8 众数 mask / 共识 mask

- **众数 mask**：出现次数最多的那张“完整 mask”（按 1.3 的严格相等判据）。
  它回答“有没有哪一次运行被别的运行完整复现过”。
- **共识 mask**：按某个规则（默认多数投票）从 π 生成的最终 mask。
  它才是要交给 CMA-ES 的那张图。

### 1.9 support（支撑集）—— 和 mask 是同一个东西

文档里出现的 "support" 指**非零系数的位置集合**，**不是截距**：

```matlab
support = find(abs(beta) > nzTol)      % 一组线性下标（1..234），列主序
mask    = abs(beta) > nzTol            % 同一个东西的 26×9 逻辑矩阵形式
```

- `fit.S.(group){m}` 存的就是这个下标向量；
- `mask(i,j)=1` ⇔ `(i,j)` 在 support 里 ⇔ 该 β 条目会进入 CMA-ES 向量；
- **偏置 `b`（9 个）永远存在**，它不属于 support、也不受 mask 约束。

所以“在当前 support 上做 refit”= **只保留这些格子、其余强制为 0，重新做一次
（带 censoring 的）最小二乘**。support、mask、0-1 图，三者说的是同一件事，
只是分别用“下标 / 逻辑矩阵 / 直观叫法”表示。

## 2. 为什么需要它：单次辨识的结构不稳

现有链路：

```
读 .sto → 26 个特征 → 加权(鲁棒)OLS → adaptive 权重 → lambda path → 选 lambda → Huber refit
```

这条链**没有任何随机数**（`Sparse Group LASSO Validation/` 下 `rng|rand` 零命中）。
所以“换 20 个种子”本身不会产生任何差异——**必须先定义随机性从哪来**。

不稳定性来自最后的选择规则：

```
minErr    = min(RMSE_refit)                  % 沿 lambda path 的最小误差
threshold = (1 + 0.05) * minErr              % 允许 5% 的误差
selected  = path 上第一个 RMSE <= threshold 的 lambda（最稀疏的那个）
```

`lambda` 是**连续的**，但“选哪个 lambda”是**离散的**：数据动一点点，选中的
lambda 就跳到隔壁一档，support（哪些格子非零）整块变化。这就是 0-1 图抖动的
物理来源，也是本方法要量化并驯服的东西。

## 3. 随机性：按步态片段重采样（run-level bootstrap）

### 3.1 输入是什么

| 输入 | 内容 |
|---|---|
| `Sparse Group LASSO Validation/moco_dataset/moco_lasso_dataset.sto` | 3001 帧 × 100 Hz（210–240 s）的激励/特征/相位表 |
| `.../moco_lasso_dataset.mat` 里的 `ds.sampleWeight` | 每帧权重（10 帧接缝为 0） |
| `ds.meta` | 记录上游来源，见 §3.4 |

> 数据本身来自：`experiments/moco/outputs/moco_inverse_solution_B30_right_final.sto`
> （MocoInverse 解，含 excitation）+ `ik_radians.mot`（IK）+ `grf_window_209p5_240.mot/.xml`
> （GRF）+ `model/human0918.osim`，经 `moco_inverse_to_lasso_dataset.m` 转成 LASSO 数据集。

### 3.2 什么叫“按片段”

把属于某个相位组的帧号按时间切成**连续段**（run）。本数据：

| 组 | 帧数 | 段数 | 每段长度 |
|---|---|---|---|
| stance（相位 0、1） | 1468 | **26** | 约 56 帧 ≈ 0.56 s |
| swing（相位 2、3、4） | 1532 | **27** | 约 57 帧 |

每一段就是“一个步态周期里该相位的一段”。一个种子做的抽样是：

```
从 26 段里，有放回地随机抽 26 段 → 拼起来 ≈ 1468 帧（有些段被抽 2 次，有些没抽到）
```

### 3.3 为什么必须整段抽，不能逐帧抽

步态数据相邻帧高度相关（同一个步态周期的连续演化）。逐帧独立抽样会**打断**这种
相关性，让重采样数据看起来比真实数据“信息更多更独立”，从而**系统性高估稳定性**
（看起来每个格子都很稳，其实只是抽样方式太温和）。

按整段抽，段内的时间结构完整保留，改动只发生在“这一批步态周期里哪几个被重复、
哪几个缺失”，这才是“换一批等效实验样本”的合理模拟。

三种模式（`resampleMode`）：

| 模式 | 做什么 | 用途 |
|---|---|---|
| `run_bootstrap`（默认） | 抽 26 段，**有放回** | 主方法 |
| `run_subsample` | 抽约 80% 的段，**不放回** | 消融：会混入“样本变少”的影响 |
| `iid_bootstrap` | 逐帧有放回 | 反面对照：预期过于“稳定” |

### 3.4 种子在哪里生效

只在**抽样**这一步：

```matlab
rs = RandStream('Threefry', 'Seed', baseSeed + k);   % 第 k 个种子 = 2026+k
idxStance = bootstrap_phase_runs(stanceRuns, 'run_bootstrap', rs);
idxSwing  = bootstrap_phase_runs(swingRuns,  'run_bootstrap', rs);
```

其余一切都不变：模型、特征、清洗、`gamma`、`rho`、`c`、`tolSelect`、lambda 网格、
Huber 常数、标准化常数 `muX/sX`。**只有“这一轮抽到哪些帧”随种子变。**

## 4. 完整 pipeline（每一步的输入 → 处理 → 输出）

```
┌ Step 0  读数据（1 次）
│   in : moco_lasso_dataset.sto/.mat
│   out: X(3001×26), X_std, Y(3001×9), w(3001×1), phaseIdxMap{stance,swing}
│   code: load_lasso_design_matrices.m
│
├ Step 1  切连续段
│   in : phaseIdxMap
│   out: 每组的段列表（26 / 27 段及其帧号）
│   code: bootstrap_phase_runs.m 内部
│
├ Step 2  对每个种子 k=1..20 重采样
│   in : 段列表 + 种子
│   out: idx_k（≈1468 + 1532 个帧号，可重复）
│   code: bootstrap_phase_runs.m
│
├ Step 3  用“完全相同的辨识程序”在 idx_k 上拟合
│   in : X(idx_k,:), Y(idx_k,:), w(idx_k)
│   out: 9 肌肉 × 2 组 的 β_final 与 support
│   code: fit_adaptive_lasso_core.m（就是原来的 fit_adaptive_lasso_phase_model 的拟合半身）
│
├ Step 4  折叠成 mask
│   in : β_final
│   out: mask_k（26×9 逻辑矩阵，每组一个）  ⇒ K×2 个 mask
│   code: lasso_stability_one_replicate.m → lasso.groups(g).mask
│
├ Step 5  汇总统计
│   in : K 个 mask
│   out: π(26×9)、逐个 mask 的出现次数、两两 Jaccard、覆盖率、
│        稳定/模糊计数、聚类
│   code: consensus_reflex_structure.m
│
├ Step 6  共识规则 → 共识 mask
│   in : π（+ 众数/medoid）
│   out: consensusMask（26×9，每组一个）
│   code: consensus_reflex_structure.m
│
├ Step 7  全量数据 + 冻结 mask 重拟合系数
│   in : 全部 3001 帧 + consensusMask
│   out: β_final, b_final（不在 mask 内的格子严格为 0）
│   code: fit_adaptive_lasso_core.m（mode='mask_override'）
│
└ Step 8  输出与质检
    out: results/lasso_controller_result_moco_consensus.mat
         results/lasso_stability_diagnostics.mat
         results/lasso_stability_*.png
    code: lasso_stability_from_design.m
```

### Step 0 细节：这里为什么只读一次

读 `.sto` 要用 OpenSim 的 `TimeSeriesTable`，9 块肌肉读 9 次，是整个流程最慢的
一段（十几秒）。20 个种子如果用同一条路重读，就是 20 倍浪费。所以把“数据加载”
单独抽成 `load_lasso_design_matrices.m`，**只跑一次**，之后每个种子只是在内存里
按帧号取子集。

### Step 3 细节：拟合那一步内部发生了什么（每个肌肉 × 每个相位组）

这是**完全没有改动**的原流程，逐句对应 `fit_adaptive_lasso_core.m`：

1. **加权 OLS（只用非截断样本）**：`y > c+tol` 的样本才当作“真实观测”，
   先用它们求出初估 `β_OLS`；再做 2 轮 Huber IRLS（抑制 excitation burst）。
   - in: `X_group`, `y_group`, `w_group`
   - out: `β_OLS`
2. **自适应权重**：`w_j = 1 / max(|β_OLS_j|, 1e-8)^gamma`（`gamma=1`）。
   系数大的格子惩罚小、系数近 0 的惩罚大（Zou 2006）。
3. **lambda path**：把 `X` 按 `w` 列缩放，从“β=0 仍最优”的 `lambda2Max` 出发，
   沿 60 个 alpha 点一路降到 `1e-4 × lambda2Max`。每个点都解一次
   censored LASSO（`sgl_fit.m`，FISTA + 回溯），并在当前 support（= 该点的
   非零格子集合，见 §1.9）上做一次 post-selection refit。
4. **选 lambda**：在 `(1+0.05)·minErr` 容差内取**最稀疏**的那个。
5. **Huber refit**：固定选中的 support，做 2 轮 Huber IRLS 得到最终系数。

> censoring 是什么意思：实测 excitation 在 0 附近被 floor 到 0.01，
> 这些样本的真实“潜在激励”可能是 0，只是观测不到。所以对它们不是最小化
> `(y−ŷ)²`，而是惩罚“预测**高于** floor”：`rho·max(ŷ−c,0)²`（`rho=50`）。
> 这样模型不会为了拟合这些“看不清”的样本而扭曲系数。

### Step 4 细节：mask 怎么从 β 得到

```
mask(i,j) = ( |β(i,j)| > 1e-5 )
```

比阈值小的数值残渣会被强制清零，保证 `mask=false` 的格子**恰好是 0**
（loader 会检查这一点，不容许“mask 说 0 但 β 有 1e-12”）。

### Step 5 细节：π 怎么算

```
π(i,j) = ( Σ_{k=1..K} mask_k(i,j) ) / K
```

注意两个组**分开算**：stance 的 π 只用 stance 的 20 个 mask，swing 同理。

### Step 6 细节：共识规则

| `consensusRule` | 规则 | 本数据会得到 |
|---|---|---|
| `majority`（默认） | `π ≥ 0.5` 保留 | 123 / 106 个条目 |
| `mode` | 出现次数最多的那张完整 mask | 实测每张只出现 1 次，退化为“任选一张” |
| `medoid` | 与其余种子平均 Jaccard 最高的那张 | 一张真实的运行结果 |
| `stability` | `π ≥ piThreshold`（默认 0.7） | 86 / 78 个条目 |

### Step 7 细节：为什么要在全量数据上重拟合

不能直接把 K 次拟合的系数取平均：bootstrap 平均会**收缩**系数，还可能把某些
格子平均成 0，反而破坏结构。正确做法是：

```
结构由共识决定（冻结） → 系数回到“全部真实数据”上重新估一次
```

这样得到的数值是“用最多信息估出来的、与结构一致的”那组数，最适合当 CMA-ES 的
初值。重拟合时仍然用 censoring + Huber，只是不再跑 lambda path（结构已定）。

## 5. 手算一个迷你例子

假设只有 4 个格子、3 个种子：

| 种子 | 格子1 | 格子2 | 格子3 | 格子4 |
|---|---|---|---|---|
| k=1 | 1 | 1 | 0 | 0 |
| k=2 | 1 | 1 | 0 | 1 |
| k=3 | 1 | 0 | 0 | 0 |

**π**：格子1 = 3/3 = 1.00；格子2 = 2/3 ≈ 0.67；格子3 = 0；格子4 = 1/3 ≈ 0.33。

**多数投票**（π≥0.5）：`[1 1 0 0]` —— 正好是 k=1 的那张。

**两两 Jaccard**：
- J(1,2) = |{1,2}∩{1,2,4}| / |{1,2,4}| = 2/3
- J(1,3) = |{1}| / |{1,2}| = 1/2
- J(2,3) = |{1}| / |{1,2,4}| = 1/3
- 平均 = (0.67+0.50+0.33)/3 = **0.50**

**覆盖率**（相对共识 `[1 1 0 0]`）：k=1 → 2/2 = 1.00；k=2 → 2/3 = 0.67；k=3 → 1/1 = 1.00。

**众数**：三张 mask 各不相同 → 众数只出现 1 次，`modeFraction = 1/3`。

这个例子把“完全相同”“Jaccard”“π”“覆盖率”“众数”全都串起来了：
**三个种子的结构没有一张完全相同，但格子 1、2 显然该保留，格子 4 只有 1/3 支持。**

## 6. 参数手册：哪些改变算法，哪些只是报告

### 6.1 改变算法的（会改变最终 mask 或系数）

| 参数 | 默认 | 作用 |
|---|---|---|
| `nSeeds` (K) | 20 | 种子数；越大 π 越准，耗时线性增长 |
| `baseSeed` | 2026 | 第 k 个种子 = baseSeed + k；换它 = 换一整套抽样 |
| `resampleMode` | `run_bootstrap` | 抽样方式（见 §3.3） |
| `consensusRule` | `majority` | 见 §6.3 |
| `tieBreak` | `include` | π 恰好 = 0.5 时算“有值”（K 为偶数时才会遇到） |
| `piThreshold` | 0.7 | **只在 `consensusRule='stability'` 时生效** |
| `fitOptions.*` | 见文档 | 原始辨识参数（`gamma/rho/c/tolSelect/...`），**所有种子共用** |

### 6.2 只影响报告的（不改变 mask）

| 参数 | 默认 | 作用 |
|---|---|---|
| `stableOnPi` | 0.9 | 报告用：π ≥ 它记作“稳定激活” |
| `stableOffPi` | 0.1 | 报告用：π ≤ 它记作“稳定不激活” |
| `conformJaccard` | 0.8 | 报告用：判定“某种子与共识同框架”的 Jaccard 线 |
| `clusterJaccard` | 0.9 | 报告用：把种子按 mask 相似度聚类的连边阈值 |
| `minStabilityJaccard` | 0.35 | **质检门限**：两两 Jaccard 均值低于它就发警告 |
| `maxRMSEIncrease` | 0.15 | **质检门限**：冻结后 RMSE 涨幅超过它就发警告 |
| `minDominantFraction` | 0.6 | 只记录在元数据里，不触发警告 |

### 6.3 `consensusRule` 到底是什么

它决定“把 K 张 mask 合成 1 张”的规则，共 4 种：

```
majority : C = (π >= 0.5)                 ← 默认，逐格子过半
stability: C = (π >= piThreshold)          ← 更严格，piThreshold 在这里起作用
mode     : C = 出现次数最多的那张完整 mask
medoid   : C = 与其余种子平均 Jaccard 最高的那张
```

**默认 `majority` 时 `piThreshold` 完全不起作用**——这是两个不同的开关，
这一点最容易混淆。

### 6.4 为什么“完全相同”不能当门限，“N/20 就选它”其实已经实现了

`majority` 有一个干净的性质：若 20 个种子里有 m 个给出**完全相同**的 mask M，
那么每个格子在 M 上的取值至少有 m 票，于是

```
π ≥ m/20   或   π ≤ 1 − m/20
```

只要 `m/20 > 0.5`（即 m ≥ 11），多数投票就**逐格还原 M**。

> **所以“13/20 个种子收敛到同一框架 → 就选这个框架”不需要额外逻辑，
> 它就是 π ≥ 0.5 的自然结果。** 这条性质写进了单元测试
> （`tests/test_lasso_stability_identification.m` Test 1），是硬约束。

本数据上恰好没有出现“13 张完全一样”的情况（真实数据抖动更多，见 §7），
但这不影响规则；只是实际生效的是“逐格子过半”而不是“整张过半”。

### 7.5 稀疏度取舍：为什么现在有 247 个参数，怎么减

#### 先澄清三件容易误会的事

1. **冻结不会让 RMSE 变低。** 冻结 = 少用参数，训练误差只会**升高**。
   之前看到的“冻结后低 0.26%”并不是稀疏带来的，而是因为 **π≥0.5 的共识是
   超集**（比单次拟合多 13 个格子）——参数更多，拟合自然略好。
2. **UN.sto 的 22/17 不能拿来比。** 那条路径的日志里 `minRefitRMSE` 是
   `1.2e-06 / 3.6e-08 / 2.5e-07`——数据本身就是由同一类线性反射律生成的，
   线性模型 1–4 项就能**精确复现**。而 MocoInverse 的 excitation 是最优控制的
   解，26 个线性特征根本不可能精确表达它（最优 RMSE 也只能到 **0.019**）。
   前者是“恢复生成系数”，后者是“近似一个富信号”，两者没有可比性。
3. **247 ≠ 26×9 全开。** 它是“每个肌肉-相位平均 13 项”，远未填满；只是比
   UN.sto 那种“2–4 项”多得多。

#### (a) lambda path 的边际收益（每块肌肉、每个相位组平均）

| 容忍误差（相对该肌肉-相位的最优 RMSE） | stance 平均项数 | swing 平均项数 |
|---|---|---|
| +2% | 14.1 | 12.6 |
| **+5%（当前 tolSelect）** | **12.7** | **11.3** |
| +10% | 10.1 | 10.1 |
| +20% | 7.7 | 7.6 |
| +50% | 4.0 | 4.6 |
| +100% | 2.7 | 3.3 |

读法：**5% 确实偏严，但它并没有“多留了一大堆”**——从 5% 放宽到 20% 只能从
12.7 项减到 7.7 项（−39%），而误差代价是 +15 个百分点。想达到 UN.sto 那种
2–4 项，必须容忍 **+50%–100%** 的误差，此时线性模型只能解释一小部分变化。

**这条曲线也能直接给“容许误差”**：用 Kneedle 判据（把 x、y 归一化后找离两端
连线最远的点）取中位曲线的膝点，得到 stance **2.0 项**（RMSE/RMSE_best = 1.67，
隐含 `tolSelect ≈ 0.67`）、swing **3.0 项**（1.50，≈ 0.50）。也就是说：
**“再加一项”的边际价值在 2–3 项之后就迅速衰减**。但要注意这个膝点**只看精度、
不看稳定性**，所以它比 §(b) 给出的方案更激进。

#### (b) π 阈值扫描：先搞清楚“训练 / 留出”是什么

**训练误差（in-sample）**：用同一批数据既拟合又打分。模型是照着这些点调的，
所以必然偏低。

**留出误差（out-of-sample / held-out）**：用模型**没见过**的数据打分。

我们怎么切分（2 折，按**步态段**而不是按帧）：

```
30 s 的 stance：26 段   →  A 折 = 第 1,3,5,… 段      B 折 = 第 2,4,6,… 段
30 s 的 swing ：27 段   →  同样按奇偶分
        ↓
在 A 上重拟合系数 → 在 B 上打分   = B 的留出误差
在 B 上重拟合系数 → 在 A 上打分   = A 的留出误差
两者平均                          = 该 π 阈值的“留出 RMSE”
```

**为什么按整段分、不按帧随机分？** 相邻帧几乎是同一个动作的连续采样，随机分帧会
让“训练里的这一帧”和“测试里的下一帧”几乎重复（信息泄漏），留出误差会假性偏低。
按整段分，测试集是**没见过的步态周期**，才回答“换一批步态还准不准”。

**“相对最优留出 +xx%”怎么算**：取所有 π 阈值里最小的留出 RMSE（本数据是
π≥0.4 的 0.02065），当作 100%，然后

```
相对值 = (本行留出 − 0.02065) / 0.02065 × 100%
```

例：π≥0.7 → (0.02240 − 0.02065)/0.02065 = **+8.5%**，意思是“为了把参数从
283 砍到 175，我在没见过的步态上多付 8.5% 的预测误差”。

> 注意这个 0.02065 的绝对水平里有很大一块是**26 个线性特征根本解释不了的**
> （模型误配），那部分无论怎么加参数都消不掉；我们只关心**不同稀疏度之间的相对差**。

**三列训练/留出的区别**：

| 列 | 拟合用 | 打分用 | 用途 |
|---|---|---|---|
| `train(full)` | 全部 3001 帧 | 全部 3001 帧 | 报告“拟合得好不好” |
| `train(fold)` | 一折（约一半段） | 同一折 | 与留出**同规模**比较，算过拟合 gap |
| `held-out` | 一折 | **另一折** | 泛化误差 |

  说明开始删掉真正有用的条目。

> 一句话：**这里没有免费午餐**。数据能支持的是“5% 容差并不错，但 247 里约
> 三成是冗余/拟合噪声”；想更简洁，就要明确接受 ~10% 的 excitation 误差，
> 把它当作给 CMA-ES 的“结构先验”而不是“精确拟合”。

### 7.6 run-level 与 i.i.d. 重采样：稳定性会被夸大多少

`sgl_fit` 确实**不看时间**，所以有人会猜两种重采样的稳定性差不多。实测（K=20）：

| 指标 | stance（run / iid） | swing（run / iid） |
|---|---|---|
| 两两 Jaccard 均值 | 0.528 / **0.668** | 0.588 / **0.749** |
| 稳定激活（π≥0.9） | 45 / **69** | 50 / **78** |
| 稳定不激活（π≤0.1） | 31 / **67** | 62 / **96** |
| 模糊条目 | 158 / **98** | 122 / **60** |
| 共识 mask nnz | 123 / 121 | 106 / 99 |
| 平均覆盖率 | 0.784 / **0.875** | 0.816 / **0.878** |

**结论：i.i.d. 把稳定性系统性夸大了，但不改变稀疏度。**

- Jaccard 高出 **0.14 / 0.16**，模糊条目几乎减半（158→98、122→60）；
- 共识 nnz 几乎一样（123 vs 121、106 vs 99）——说明差异不在“选出多少项”，
  而在“你有多少信心”。

原因：逐帧有放回会把重复帧散布到所有步态段里，每个 replicate 看起来都像
“见过了全部步态”；而整段重采样会让整段步态被丢弃/重复，更接近真实的数据
获取过程。所以**报告稳定性必须用 run-level**；i.i.d. 只适合当反面对照
（代码：`compare_bootstrap_resampling.m`，结果存
`results/lasso_bootstrap_mode_comparison.mat`）。

## 8. 和 CMA-ES 的关系

```
lasso_controller_result_moco_consensus.mat
        │  mask（冻结） + β（初值）
        ▼
load_lasso_reflex_controller.m → initPara（长度 = nnz_stance+9+nnz_swing+9 = 247）
        ▼
unpack_lasso_reflex_params.m（每帧 beta(~mask)=0）
        ▼
CMA-ES（只动有值格子的数值）
```

- **结构**：由本方法决定，CMA-ES 无法增减维度；
- **数值**：只是 initial guess。真实数据与仿真模型之间有 gap（real2sim gap），
  LASSO 的系数不可能直接让模型走起来，这正是 CMA-ES 要修的东西。
- 因此：**不要把 LASSO 的 RMSE 当作“最终质量”，它只衡量“在数据上拟合得好不好”**。

## 9. FAQ

**Q1：为什么 π<0.9 就算“模糊条目”，而不是 0.8 / 0.7 / 0.6？**
因为 0.9/0.1 只是**报告用的约定**（“20 个里最多 2 个反对”），它**不参与**
共识 mask 的生成。换一个阈值只会改变报告里三个计数的划分，不会改变 controller。
下面的表说明改阈值会得到什么（同一份 π）：

| “稳定激活”阈值 | stance 计数 | swing 计数 |
|---|---|---|
| ≥ 0.90（当前） | 45 | 50 |
| ≥ 0.85 | 53 | 61 |
| ≥ 0.80 | 59 | 67 |
| ≥ 0.70 | 79 | 78 |
| ≥ 0.60 | 97 | 91 |

所以“0.9 是不是太严”取决于你想在报告里强调什么；判决只用 π≥0.5。

**Q2：`piThreshold` 在哪里起作用？**
只在 `consensusRule='stability'` 时。默认 `majority` 用的是固定的 0.5，
`piThreshold` 完全被忽略。

**Q3：既然共识是“过半”，为什么会比单次拟合（234）还多（247）？**
因为多数投票保留的是“至少 11 个种子选中”的格子，而单次全量拟合在每个
肌肉-相位上只选了一个 lambda，两个集合不完全重合：共识丢掉了一些单次拟合
独有的格子，也纳入了不少“多数种子都选、但单次拟合没选”的格子，净多 13 个。
多出来的格子由 CMA-ES 决定保留与否（它可以把系数调成接近 0，但维度省不掉）。

**Q4：想让参数更少怎么办？**
把 `consensusRule` 改成 `'stability'`、`piThreshold` 设 0.7，得到
86+9+78+9 = **182** 个参数，然后跑一次看 `rmseDelta` 能不能接受。
下面是同一份 π 在不同阈值下的参数总数：

| π 阈值 | stance | swing | 总参数 |
|---|---|---|---|
| >0（并集） | 225 | 201 | 444 |
| **0.5（当前 majority）** | **123** | **106** | **247** |
| 0.6 | 97 | 91 | 206 |
| 0.7 | 79 | 78 | 175 |
| 0.8 | 59 | 67 | 144 |
| 0.9 | 45 | 50 | 113 |

**Q5：为什么种子之间 RMSE 会差很多（in-bag 那个 +5.3%）？**
因为每个种子都在“自己抽到的数据”上评估自己，越重复抽样越容易拟合，
这是 in-bag 的固有偏差。所以质检用的是**全量**参照拟合，不是种子 RMSE。

**Q6：换 `baseSeed` 结果会变吗？**
会。它是“换一整套抽样”。但 π 的稳定部分应当基本不变——如果两块 baseSeed 的
π 差很多，说明结构本身不可靠。这也是一个很便宜的复核手段。

**Q7：能不能不加随机性，只调 `tolSelect` 看结构？**
那测的是“对某个超参的敏感性”，不是“统计稳定性”。两者都有用，但结论不能互换。
本方法固定超参、只换样本，所以 π 的含义是“在等效数据扰动下的可重复性”。
